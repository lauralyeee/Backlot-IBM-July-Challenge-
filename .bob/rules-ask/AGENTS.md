## Where things actually live

- All AI generation: `backend/main.py` → `backend/watsonx.py`
- Prompt construction: `backend/generation.py`
- Relevance ranking: `backend/retrieval.py`
- DB access: `backend/db.py` (WAL mode SQLite, 2 tables: `worlds`, `assets`)
- Frontend API surface: `src/lib/api.js` (thin fetch wrappers, no library)
- Static world archetypes + seed data: `src/lib/worldData.js` (4 personas: odyssey, highfantasy, scifi, urban)
- Role definitions mirrored server-side: `backend/lib/worldData.py` (ROLES only — not PERSONAS, TYPES, TYPE_META)

## Non-obvious data shapes

- `world` object from the API always has `rolesFull` added by `_enrich_world()` (server) and re-added in `App.jsx` (client). Raw DB rows do not contain it.
- `assets[].offline === true` means the asset was generated by the local fallback, not the LLM, but it IS saved to SQLite.
- `canon_block()` in `retrieval.py` truncates each asset's content to 220 chars before injecting into prompts.
- The `/generate` endpoint returns `{ asset, grounding, offline?, error? }` — `grounding` is the top-10 retrieved assets that were sent to the model.
